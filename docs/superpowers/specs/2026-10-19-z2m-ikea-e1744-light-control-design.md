# Zigbee2MQTT IKEA E1744 조명 제어 블루프린트 설계

## 목적

IKEA SYMFONISK 1세대 회전 노브(E1744)의 MQTT 메시지를 직접 받아 조명의
밝기, 색온도, 색상, 채도를 조절한다. 자동화를 만들 때 대상 조명과 회전 기능
하나를 선택한다. 한 번·두 번·세 번 클릭에는 사용자가 각각 원하는 HA 동작을
지정한다.

배포물은 자동화 블루프린트 YAML 한 파일이다. Z2M action 센서, 기기 레지스트리
ID, 상태 저장 도우미, 별도 실행 스크립트에 의존하지 않는다. 클릭으로 회전 모드를
바꾸는 기능과 누른 채 회전하는 기능은 포함하지 않는다.

## 구성

MQTT 트리거가 알려진 동작을 걸러서 받아 `choose`로 클릭과 회전을 분기한다.
회전 분기는 시작 값을 한 번 읽고, 계산한 목표값을 순차적으로 적용한다.

- 자동화 실행 방식은 `restart`다. 새 유효 조작이 이전 실행의 남은 단계를 중단한다.
- 한 실행 안에서는 조명 서비스 호출을 순서대로 처리한다.
- 정지 신호도 트리거로 받아 진행 중인 회전을 중단한다.
- 배터리 보고처럼 동작이 없는 메시지는 트리거 단계에서 제외한다.
- 자동화 하나가 한 노브와 한 조명 또는 조명 그룹을 담당한다.

[Tap Dial Engine](https://github.com/kkqq9320/homeassistant/blob/main/blueprints/automation/z2m_philips_hue_tap_dial_engine.yaml)의
색상·채도 계산 규칙을 따른다. 해당 Engine의 버튼 프로필, Worker, 영구 세션 저장은
E1744의 고정 회전 기능에 필요하지 않아 도입하지 않는다.

## MQTT 계약

구독 경로는 `base_topic`과 Z2M의 정확한 `friendly_name`을 `/`로 연결한다.
HA 표시 이름이나 action 센서 이름으로 topic을 추정하지 않는다.
기기 topic의 JSON 본문에서 문자열 `action`을 읽는다.

| `action` | 처리 |
|---|---|
| `toggle` | 한 번 클릭 동작을 한 번 실행 |
| `brightness_step_up` | 두 번 클릭 동작을 한 번 실행 |
| `brightness_step_down` | 세 번 클릭 동작을 한 번 실행 |
| `brightness_move_up` | 오른쪽 회전 실행 시작 |
| `brightness_move_down` | 왼쪽 회전 실행 시작 |
| `brightness_stop` | 진행 중인 실행 중단 후 종료 |

빈 메시지, 잘못된 JSON, JSON 객체가 아닌 값, 빠진 `action`, 빈 문자열,
문자열이 아닌 `action`, 알려지지 않은 동작은 실행을 만들지 않는다.
같은 클릭 값이 연속으로 와도 각 메시지를 별도 클릭으로 처리한다.
클릭 횟수를 시간으로 추정하거나 클릭 판정을 위해 추가로 기다리지 않는다.

동일 방향의 `brightness_move_*`가 다시 와도 새 회전 실행으로 처리한다.
각 실행의 기준값과 제한 시간은 새로 시작한다. 따라서 최대 반복 시간은
마지막 회전 시작 메시지 뒤의 실행에 적용되며, 여러 메시지에 걸친 누적 시간
제한으로 표현하지 않는다.

## 입력과 기본값

설정 화면은 연결, 회전 기능, 조절량, 클릭 동작으로 나눈다. 조절량은 접을 수
있는 고급 설정으로 둔다.

| 입력 ID | 표시·의미 | 기본값과 범위 |
|---|---|---|
| `base_topic` | Z2M 기본 topic | `zigbee2mqtt` |
| `knob` | Z2M 기기 이름 | 필수 문자열 |
| `target_light` | 대상 조명 | 필수 `light` 엔티티 한 개 |
| `rotation_mode` | 회전 기능 | `brightness`; 아래 네 가지 중 선택 |
| `brightness_step_pct` | 반복당 밝기 변화량 | 2%p; 1~100%p |
| `color_temp_step_kelvin` | 반복당 색온도 변화량 | 100 K; 1~10000 K |
| `hue_step_percent` | 반복당 색상환 이동 비율 | 2%; 1~100% |
| `saturation_step_pct` | 반복당 채도 변화량 | 2%p; 1~100%p |
| `repeat_interval_ms` | 한 번 처리한 뒤 다음 반복까지 대기 | 200 ms; 100~2000 ms |
| `max_rotation_seconds` | 회전 실행의 최대 반복 시간 | 10초; 1~30초 |
| `action_click_short` | 한 번 클릭 동작 | `[]`; action 선택기 |
| `action_click_double` | 두 번 클릭 동작 | `[]`; action 선택기 |
| `action_click_triple` | 세 번 클릭 동작 | `[]`; action 선택기 |

조절량은 물리적인 회전 각도나 한 칸당 변화량이 아니다. E1744의 시작·정지
신호 사이에서 실행되는 반복 한 번의 변화량이다. 서비스 호출이 오래 걸려도
밀린 반복을 한꺼번에 따라잡지 않는다.

`target_light`는 현재 속성을 읽어야 하므로 `target` 선택기가 아닌 단일
`entity` 선택기를 사용한다. 여러 조명은 HA의 조명 그룹 엔티티로 지정한다.
그룹은 보고된 집계 속성을 기준으로 동작하며 개별 구성원의 상대값 유지 기능은
제공하지 않는다.

클릭 입력에는 조명 전환, 스위치, 음악 재생 등의 기본 동작을 넣지 않는다.
사용자는 GitHub에서 블루프린트를 가져온 뒤 자동화 편집기에서 직접 설정한다.
비어 있는 클릭 동작도 회전 중단 효과는 갖지만, 서비스를 호출하지 않는다.

## 네 가지 회전 기능

| 저장 값 | 표시 이름 | 오른쪽 | 왼쪽 | 범위·유지값 |
|---|---|---|---|---|
| `brightness` | 조명 밝기 | 밝기 증가 | 밝기 감소 | 1~100%; 색상 관련 값 유지 |
| `color_temperature` | 조명 색온도 | 높은 K, 차갑게 | 낮은 K, 따뜻하게 | 조명의 지원 범위; 밝기 유지 |
| `light_hue` | Light Hue — 색상 | 색상환 정방향 | 색상환 역방향 | 0~360° 순환; 채도·밝기 유지 |
| `light_saturation` | Light Saturation — 채도 | 선명하게 | 흰색에 가깝게 | 0~100%; 색상·밝기 유지 |

모든 회전 기능은 켜진 조명만 조절한다. 회전으로 전원을 켜거나 끄지 않는다.
밝기의 하한은 1%이며, 전원 제어는 사용자가 클릭 동작에 지정한다.
다른 자동화나 사용자가 조명을 끄면 다음 반복에서 종료한다.

### 값 계산

오른쪽은 `direction = 1`, 왼쪽은 `direction = -1`이다. 실행을 시작할 때
선택한 기능의 기준값을 읽고, 반복마다 직전 목표값에 변화량을 더한다.
같은 실행에서 늦게 보고된 조명 상태를 반복해서 기준값으로 읽지 않는다.
새 회전 실행은 그 시점에 HA가 보고하는 조명 상태를 새 기준으로 사용한다.

- 밝기: `brightness`의 0~255 값을 백분율로 변환하고, 반복마다 지정한 %p를
  더한다. 결과를 1~100%로 제한하고 `brightness_pct`로 보낸다.
- 색온도: 반복마다 지정한 K를 더하고 `min_color_temp_kelvin`과
  `max_color_temp_kelvin` 사이로 제한한다. `color_temp_kelvin`으로 보낸다.
- 색상: 반복마다 `direction × hue_step_percent × 3.6`도를 더하고 360으로
  나눈 나머지를 사용한다. 2%는 7.2°다. 기존 채도를 함께 담은 `hs_color`로 보낸다.
- 채도: 반복마다 지정한 %p를 더하고 0~100으로 제한한다. 기존 색상을 함께
  담은 `hs_color`로 보낸다.

색상·채도 내부 값은 소수 셋째 자리까지 유지한다. 색상 360°는 0°로 정규화한다.
채도가 0이면 색상을 바꿔도 흰색으로 보인다. 색상 조작이 채도를 자동으로 높이지
않는다. 색온도·색상·채도 명령에는 밝기 변경 필드를 추가하지 않는다.

목표값이 이미 한계에 있어 바뀌지 않으면 같은 서비스 명령을 계속 보내지 않는다.
반복 대기는 유지하여 정지나 새 조작으로 종료할 수 있게 한다.

## 반복과 중단

1. 회전 시작 메시지를 받으면 대상과 현재 속성을 검증한다.
2. 유효하면 첫 변화량을 즉시 적용한다.
3. 서비스 호출이 끝난 뒤 반복 간격만큼 기다리고 다음 변화량을 적용한다.
4. 새 클릭·회전·정지 메시지는 `restart` 방식으로 기존 실행을 중단한다.
5. 제한 시간에 도달하면 다음 반복을 시작하지 않는다. 대기 시간도 남은
   제한 시간을 넘겨 잡지 않는다.

이미 전달한 조명 명령의 효과를 중단 시점에 되돌리지는 않는다. 중단 후에는
이전 실행에서 새 명령을 추가로 보내지 않는다. 별도 스크립트를 비동기로 실행하는
사용자 클릭 동작의 수명은 그 스크립트의 실행 방식에 따른다.

HA 재시작이나 자동화 다시 불러오기는 진행 중인 회전을 종료한다. 이전 실행을
복원하거나 남은 반복을 재생하지 않는다.

## 속성 검증과 오류 처리

- 수치 검증에서는 boolean과 유한하지 않은 값을 제외한다.
- `off`, `unknown`, `unavailable`, 없는 대상은 조명 명령을 보내지 않고 종료한다.
- 선택한 기능을 대상이 지원하는지 `supported_color_modes`로 확인한다.
  색상과 채도는 `hs`, `xy`, `rgb`, `rgbw`, `rgbww` 계열의 색상 지원 대상에서만
  사용한다. 색온도 전용 전구에는 색상 명령을 보내지 않는다.
- 밝기 또는 현재 색온도가 숫자가 아니면 0으로 대체하지 않고 종료한다.
- 색온도는 현재값과 양쪽 지원 한계가 유효한 양수인지 확인한다.
  뒤집힌 지원 범위는 오류로 처리한다.
- 색상은 유효한 `hs_color`의 색상 값이 필요하다. 숫자가 아니거나 0~360을
  벗어나면 종료한다. 채도가 없거나 숫자가 아니면 Tap Dial Engine과 같이 50을
  사용한다. 숫자인 채도가 0~100을 벗어나면 종료한다.
- 호출 오류를 숨긴 채 반복하지 않는다. 해당 실행을 끝내고 HA 실행 추적에
  남긴다. 속성 검증으로 종료할 때도 이유를 추적에서 확인할 수 있게 한다.

테스트 도구의 구체적인 의존성 버전은 구현 시 테스트 설정에 고정한다.

## 로컬 검증과 게시 기준

구현 전에 실패하는 동작 시험을 작성한다. 별도 계산 모델의 결과만 맞추지 않고,
실제 블루프린트를 확장한 자동화와 템플릿을 로컬 HA 실행기로 시험한다.
시험 대상 조명과 클릭 동작은 테스트용 엔티티와 서비스로 대체한다.

필수 검증은 다음과 같다.

1. YAML 파싱, 블루프린트 스키마, 기본 입력 확장, 자동화 스키마 검증.
2. MQTT의 여섯 동작 연결, 잘못된 메시지 무시, 동작 없는 메시지가 회전을
   끊지 않는지 확인.
3. 클릭 기본값 세 개가 빈 목록이고, 테스트용 동작을 넣으면 해당 클릭에만
   실행되는지 확인. 같은 클릭 메시지의 연속 수신도 검증.
4. 네 회전 기능의 양방향 계산, 한계값, Hue 순환, 반대 색상 성분·밝기 유지.
5. 늦은 조명 상태 보고에도 같은 실행의 목표값이 연속해서 변하는지 확인.
6. 반복 사이뿐 아니라 서비스 호출 도중의 정지·반대 방향·클릭 처리 확인.
   새 조작 이후 이전 실행이 추가 명령을 만들지 않아야 함.
7. 반복 간격, 실행 제한 시간, 동일 방향 재수신의 재시작 규칙, 조명 꺼짐과
   사용할 수 없는 상태, 속성 누락, 서비스 오류 검증.
8. 최소 지원 버전과 개발 검증 버전에서 자동화 로딩·실행 확인. 최소 버전에서
   동작하지 않는 구문은 수정하거나 지원 하한을 근거와 함께 다시 정함.
9. 기존 Aqara 테스트를 포함한 저장소 회귀 시험, 문서 링크·입력 ID·가져오기
   주소 검사.

로컬 시험을 마친 뒤 GitHub에 블루프린트, 가이드, 테스트를 함께 게시한다.
게시된 기본 브랜치에서 YAML을 다시 내려받아 검증한 산출물과 같은지 확인하고,
가져오기 주소가 실제 파일을 가리키는지 확인한다.

로컬 시험 보고서에는 사용한 HA 버전, 시험 결과, 실행한 검증 범위를 남긴다.
실제 노브의 MQTT 패킷과 조명의 반응은 로컬 시험과 별도로 기록한다.
HA에서 가져오기, 실제 대상 선택, 클릭 동작 설정은 설치 단계에서 수행한다.
